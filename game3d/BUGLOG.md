# game3d BUGLOG — the bug-fixing loop's queue

**How this works (Hiro + Claude + the `game3d-bugfix` schedule):**
- Anyone adds bugs under **OPEN** — one line each: `- [BUG-NNN] description (reported YYYY-MM-DD by who)`. Screenshots can be referenced by describing them; keep entries concrete ("X happens when Y, should Z").
- The `game3d-bugfix` scheduled task (every 10 min) fixes **ONE open bug per run**, topmost first, then MOVES the entry to **FIXED** with a dated note of what changed and how it was verified, and appends a short entry to the repo-root PROJECT_LOG.md tagged `[bugfix-schedule]`.
- Bugs too big or ambiguous for a small autonomous fix get retagged `[NEEDS HIRO]` in place and skipped.
- Ground rules for the fixer: EDIT game3d/ only — but game/src/combat/pit.js may be READ (never written) as the porting reference when a bug entry cites it; one bug per run; entries tagged [NEEDS-FABLE] are skipped (they need the interactive session, e.g. art generation); a bug marked "split across runs" may stay OPEN with an appended progress note until its last piece lands; minimal fixes, no redesigns; respect standing decisions (SOLO default on, sheet-flipbook art direction, claw-fiend-only summons, rig retired behind ?rig=1); no art generation unless the bug entry explicitly asks for it; verify with node --check on the extracted inline script — and if the shell mount serves arena.html TAIL-TRUNCATED (known hazard), verify the edited region standalone + confirm via the Read tool that the file still ends with `</html>` instead of "fixing" phantom corruption.
